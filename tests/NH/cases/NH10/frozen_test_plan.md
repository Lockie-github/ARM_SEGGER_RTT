## 1. 测试项目

### 1.1 不需要 MCU 硬件的测试

可执行测试桩，以验证与 CPU 架构无关的格式化、数值边界、配置预处理和错误处理逻辑；
该结果不作为目标平台编译兼容性、性能或资源结论。桩函数只能记录调用、模拟可写空间
和返回值，不得修改被测格式化、数值转换、标签截断或帧组装逻辑。目标代码必须使用
Arm GNU 交叉工具链构建并检查最终 ELF，不能仅以主机编译或单个源文件编译成功判定通过。

#### 2.1.2 被测接口和关键配置

本轮公开宏共 13 个：

| 类别 | 接口 |
|---|---|
| 等级日志 | `log_info`、`log_debug`、`log_warn`、`log_err` |
| 通用输出 | `log_print`、`log_string` |
| legacy 浮点 | `log_float`、`log_float_label` |
| typed 整数/指针 | `log_i32`、`log_u32`、`log_hex32`、`log_pointer` |
| typed 浮点 | `log_f32` |

必须覆盖的关键配置如下。`0/1` 组合不能只验证编译，必须同时验证输出、调用次数、
符号和依赖符合该开关的职责。

| 配置 | 默认值 | 验证重点 |
|---|---:|---|
| `RTT_LOG_ENABLE` | 1 | 关闭后 13 个宏均不求值，日志专用代码可裁剪 |
| `LOG_ENABLE_LITE` | 0 | 只改变等级日志前缀/颜色，不影响其他 9 个接口 |
| `RTT_LOG_USE_COLOR` | 1 | 只改变非 Lite 等级日志，不影响 typed 和浮点 |
| `LOG_ENABLE_INFO/DEBUG/WARN/ERROR` | 1 | 四个等级独立裁剪 |
| `LOG_ENABLE_PRINT/STRING/FLOAT` | 1 | 三类既有功能独立裁剪 |
| `LOG_ENABLE_TYPED` | 0 | 同时控制 4 个整数/指针 typed 接口 |
| `LOG_ENABLE_TYPED_FLOAT` | 0 | 独立控制 `log_f32`，不依赖 `LOG_ENABLE_TYPED/FLOAT` |
| `RTT_FLOAT_USE_MODFF` | 0 | 位解析与 modff 输出等价；旧宏 `HARD_FPU_ENABLE` 编译失败 |
| `RTT_LOG_FLOAT_FAST_PATH` | 0 | 只优化 legacy 有限浮点；不改变输出；不控制 `log_f32` |
| `RTT_WRITE_SKIP_USE_ASM` | 0 | 仅在 `RTT_USE_ASM=1` 时改变 Skip 分发，不改变 API 返回语义 |
| `RTT_USE_ASM` | 自动 | M0 保持 C 路径；ARMv7-M 可自动启用，也能强制关闭 |
| `RTT_LOG_BUFFER_INDEX` | 0 | 所有已启用日志统一写入合法通道，越界配置编译失败 |

#### 2.1.3 执行和证据规则

1. 先执行全部无硬件项目并冻结缺陷，再按 H7B0、F042、F103、F411 顺序逐板执行。
2. 固定一块板后完成其 Make/CMake、Debug/Release 和 HW-01～HW-09，再更换主板。
3. 每次切换开关、优化等级或工程类型都全量清理并重新烧录，启动日志携带唯一构建 ID。
4. 所有比较均保存两侧原始数据和规范化差分，不允许仅凭终端观察判定。
5. 自动脚本退出码非 0 必须判为失败；脚本只打印差异但没有断言时不得判为通过。
6. 当前 `tests/NH/run_nh.py` 是统一执行入口，单项实现位于 `tests/NH/cases/NHxx/run.sh`；只有其断言覆盖本节要求时才能充当证据。

### 2.2 不需要 MCU 硬件的测试要求

#### NH-01 测试桩质量与 Arm 构建检查

**测试项目描述**

使用系统 Clang 运行与架构无关的自动测试并发现内存及未定义行为；目标编译质量、架构
兼容性和最终依赖只通过 Arm GNU 交叉工具链及实际 MCU 工程判定。

**环境与工具**

- 2.1 节规定的 macOS 系统 Clang 和 Arm GNU 交叉工具链；不使用主机 GNU/GCC。
- ASan、UBSan、Cppcheck 或 clang-tidy、覆盖率工具、`nm`、`objdump` 和 map 文件。

**测试步骤**

1. 使用系统 Clang 以 C11 严格告警构建默认、全开、仅 typed、仅 typed float 和全关测试桩；这些构建只服务于自动断言。
2. 对功能测试分别启用 ASan、UBSan；对数值转换运行全部边界与随机差分输入。
3. 使用 Cppcheck 或 clang-tidy 扫描本仓库修改过的 C/H 文件，记录工具版本和豁免理由。
4. 使用覆盖率工具记录 `rtt_printf.c`、`rtt_log.c`、`rtt_float.c` 的行/分支覆盖率。
5. Arm GCC 对 M0、M3、M4F、M7 以 `-O0/-Os` 编译并链接最终探针 ELF。

**测试目的和预期结果**

- Clang 测试桩零告警、零 sanitizer 报告且退出码为 0；不据此声明 MCU 编译兼容性。
- 修改代码行覆盖率不低于 90%，分支覆盖率不低于 80%；未覆盖分支逐条说明。
- M0 ELF 不出现因 typed 十进制或默认浮点位解析新增的 `__aeabi_*div*`/`__udivsi3`。

#### NH-02 等级日志 API

**测试项目描述**

验证四个等级宏在完整、无颜色和 Lite 模式下的帧结构、独立裁剪及失败返回路径。

**环境与工具**

- macOS 系统 Clang 测试桩环境；可记录二进制输出、写入次数及返回值的 RTT 桩。

**测试步骤**

1. 对四个等级分别测试普通正文、空正文、格式参数和连续混合输出。
2. 覆盖完整有颜色、完整无颜色和 Lite 三种模式，逐字节比较 ANSI 序列、等级文字和换行。
3. 模拟写入成功、首次失败和正文/后缀阶段失败，核对返回值与底层调用序列。
4. 逐个关闭等级开关，以带副作用表达式调用对应宏。

**测试目的和预期结果**

- 完整模式前缀和颜色正确，颜色在换行前复位；无颜色模式保留等级；Lite 只输出正文和换行。
- 每个开关只影响对应等级；关闭后参数不求值，相关不可达代码可被链接器回收。

#### NH-03 通用输出 API

**测试项目描述**

验证无帧格式化输出和原始字符串输出的职责边界、返回语义及禁用行为。

**环境与工具**

- macOS 系统 Clang、RTT 写入桩、二进制比较和副作用计数测试程序。

**测试步骤**

1. `log_print` 覆盖纯文本、格式参数、`%%`、显式换行和无换行，确认不自动添加帧。
2. `log_string` 覆盖普通、空串、内嵌换行、含 `%`、长字符串和 `NULL`。
3. 记录写入通道、调用次数、请求长度、返回值；分别关闭 PRINT/STRING 和总开关。

**测试目的和预期结果**

- `log_print` 直接遵循 `SEGGER_RTT_printf` 语义，不加等级、颜色或换行。
- `log_string` 原样输出；`NULL` 返回 `-1` 且不写入；禁用后返回 0 或空语句且参数不求值。

#### NH-04 格式化器

**测试项目描述**

验证精简 formatter 的全部公开格式、错误格式策略、长消息 flush 和字符计数。

**环境与工具**

- macOS 系统 Clang、可编程 RTT 桩、表驱动边界用例和本轮重建的 `release` 对照源码。

**测试步骤**

1. 覆盖 `%c/%d/%u/%x/%X/%s/%p/%%`，以及已声明的 `-`、`0`、`+`、宽度和精度。
2. 覆盖 `INT_MIN/MAX`、`UINT_MAX`、空/NULL 字符串、主机和 Arm 指针位宽。
3. 覆盖动态精度、负精度、末尾 `%`、未知转换和不支持的 `#`、长度修饰符。
4. 以 1、8、默认三种格式化缓冲大小输出跨多次 flush 的长文字、宽字段和字符串。
5. 与执行时重新构建的 `release` 在共同支持集合上做逐字节及返回值差分。

**测试目的和预期结果**

- 支持格式输出和字符计数正确，长输出不截断、不越界、不重复。
- 不支持或不完整格式按约定保留原文且不错误消费参数。
- `SEGGER_RTT_PRINTF_BUFFER_SIZE=0` 在编译期失败。

#### NH-05 浮点日志族

**测试项目描述**

验证 legacy 与 typed 浮点 API 的数值规范，并验证转换核心和快速路径之间的等价性。

**环境与工具**

- 支持 IEEE-754 binary32 的主机环境、原始位模式生成器、RTT 桩、`nm` 和可选 `libm`。

**测试步骤**

1. 对 legacy 两接口和 `log_f32` 使用相同位模式集合：正负零、次正规数、`0.001` 邻域、整数边界、`2^32` 邻域、NaN、正负 Inf。
2. 覆盖普通、空、NULL、46 B、47 B、超长和含 `%` 标签；验证 legacy 与 typed 标签规则的差异。
3. 分别构建 `RTT_FLOAT_USE_MODFF=0/1`，比较所有规范输出；检查 modff 依赖只在开关开启且功能可达时存在。
4. 对 legacy 分别构建 `RTT_LOG_FLOAT_FAST_PATH=0/1`，验证短标签有限数走预期路径，特殊值和过长标签回退 formatter。
5. 证明 `log_f32` 始终单次非格式化写入，且不受 FAST_PATH、Lite、颜色和 `LOG_ENABLE_TYPED` 影响。
6. 使用旧宏 `HARD_FPU_ENABLE` 构建，检查明确的重命名诊断。

**测试目的和预期结果**

- 普通值固定三位并直接截断；小于 `0.001` 的负值和负零规范为 `0.000`。
- NaN/Inf/Overflow 文本与符号正确；位解析和 modff 对规范用例逐字节一致。
- `log_f32` 标签最多 46 B，整帧一次提交；短写返回负值，不产生第二次尝试。

#### NH-06 配置矩阵与代码裁剪

**测试项目描述**

验证每个公开配置只影响其负责的行为，并能在最终链接产物中真实裁剪代码与依赖。

**环境与工具**

- 主机及 Arm 编译器、预处理器、`nm`、`size`、`objdump`、map 和副作用探针。

**测试步骤**

1. 覆盖 2.1.2 的每个开关单独翻转，以及默认、全开、全关、最小通用、仅 typed、仅 typed float、typed+typed float 配置。
2. 对 13 个宏以自增函数构造 Label、Value 和可变参数，验证禁用时均不求值。
3. 用预处理输出、`nm`、map 和 undefined symbol 检查函数、formatter、颜色字符串、modff 和除法辅助依赖。
4. 覆盖 `LOG_ENABLE_TYPED_FLOAT=1` 且 `LOG_ENABLE_TYPED=0/LOG_ENABLE_FLOAT=0` 的独立性。
5. 覆盖合法非零通道、等于 Up Buffer 数量和大于数量的通道值。

**测试目的和预期结果**

- 开关职责互不串扰；全关构建无参数副作用且不保留日志实现。
- 仅 typed 配置不链接通用 formatter；仅 typed float 不依赖 legacy float 或整数 typed API。
- 日志启用时非法通道在编译期失败；总开关关闭时通道不参与运行访问。

**环境与工具**

**测试步骤**

4. 修改配置后执行增量构建和干净重建，通过依赖文件及对象哈希确认相关单元已重编译。
5. 以静态断言检查应用与 `SEGGER_RTT.c` 看到的宏和控制块布局一致。

**测试目的和预期结果**

#### NH-08 RTT 写入路径

**测试项目描述**

验证 `SEGGER_RTT_WriteNoLock` 的模式语义，以及 Skip C/汇编分发开关的行为等价性。

**环境与工具**

- 可直接初始化 RTT 控制块的主机测试、Arm GCC、反汇编工具及可执行 ARM 目标或仿真环境。

**测试步骤**

1. 直接测试 `SEGGER_RTT_WriteNoLock` 的 Skip 模式：0 B、1 B、刚好可写、差 1 B、满缓冲和跨末尾回绕。
2. 在 ARMv7-M 构建 `RTT_WRITE_SKIP_USE_ASM=0/1`，检查 C 对象的调用目标与汇编符号。
3. 在 M0 强制 `RTT_WRITE_SKIP_USE_ASM=1`，确认因 `RTT_USE_ASM=0` 保持 C 路径。

5. 覆盖 TRIM、BLOCK 和非法 Flags，确认新分发开关不影响非 Skip 分支。

**测试目的和预期结果**

- Skip 对非零写入只允许整帧接受或整帧拒绝；失败时 `WrOff` 和缓冲内容不变。
- 汇编布尔返回值正确转换为 `NumBytes/0`，0 B 不调用汇编且返回 0。
- 开关关闭保持原 C 行为，C/ASM 对全部规定状态等价。

#### NH-11 typed 整数与指针日志

**测试项目描述**

**环境与工具**

**测试步骤**

1. `log_i32` 覆盖 `0/1/-1/INT32_MAX/INT32_MIN`；`log_u32` 覆盖 `0/1/UINT32_MAX`。
2. `log_hex32` 覆盖 `0/1/0x89ABCDEF/UINT32_MAX`，检查 `0x` 加 8 位大写十六进制。
3. `log_pointer` 在 32 位 Arm 和 64 位主机覆盖 NULL、低地址、最高位非零值，检查完整指针宽度。
4. 每个接口覆盖 NULL、空、普通、含 `%`、45/46/47 B 和超长标签。

6. 在 Lite/颜色四组合和非零通道下重复，检查输出不变且通道正确。

**测试目的和预期结果**

#### NH-12 写入失败与路径等价性

**测试项目描述**

**环境与工具**

**测试步骤**

1. 对等级、print/string、legacy float、5 个 typed API 模拟返回 0、短写和正常写入。
2. 对 formatter 长消息在第 1/2/中间/最后一次 flush 失败，记录停止位置和已接收字节。
3. 对 typed 断言一次写入，任何非完整返回均为错误；下一次调用不继承错误状态。

**测试目的和预期结果**

- 三组优化/备用路径在各自规范范围内输出和状态完全等价；任何差异都有明确设计依据和定向用例。
